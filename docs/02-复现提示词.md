# 02 · 复现提示词（导演版制作任务书）

> 用法一：直接整段贴给任一具备代码执行能力的模型，它能按这份任务书独立完成一支同水准的短片。
> 用法二：只改顶部【填参区】，可换成别的产品/主题，风格规范不需要动。
> 本文是"任务书"，不是"参考答案"。它规定**约束**与**验收**，把创意留给执行者——这才是它有效的原因。

---

# 填参区（只改这里）

- **主题**：Claude Sonnet 5.5 的 30 秒自我介绍片（可替换为任意产品/概念）
- **时长**：30.000 秒 / 900 帧 / 30fps / 1920×1080（不可改）
- **语言**：中文文案（配乐与音效无对白）
- **交付**：可播放 MP4 + 完整源代码 + 一页制作说明

# 全文（复制以下全部内容）

你现在同时担任这部片子的 **创意总监、动效设计师、作曲、以及写它的工程师**。你的产出是一支能放进顶级动效设计师作品集的 30 秒成片，不是方案、不是分镜表、不是母版截图。

## 0 · 三件必须最先做的事

**0.1 事实核实（最多花 3% 的时间）**
搜索并只采信一手来源。把结论写成一句**可关闭的句子**：`已核实：<事实清单> / 来源 <域名> / 日期 <YYYY-MM-DD>`。
凡是无法核实的数字（跑分、价格、与竞品的比较）**一律不用**。把"不能用"的清单变成交付前的一次 `grep`，**用 0 命中当证据**。
画面中出现的所有数据、代码、表格都必须标注 `示意画面` / `示意数据`。

**0.2 环境勘察（一条命令探完）**
探测：CPU 核数、内存、有没有 GPU、有没有 canvas/skia/chromium/moviepy、有哪些 CJK 字体、ffmpeg 是否可用、磁盘余量。
**用探测结果决定技术栈，不是用偏好决定。** 如果只有 1 核 3GB，就不要选浏览器渲染。

**0.3 母题决策（这一步决定成片好坏，别急着写代码）**
写出至少 3 个候选母题，用这 5 条打分，择优：

| 判据 | 问自己 |
|---|---|
| **复用度** | 一个原语能不能同时担任：光标 / 标点 / 图标 / 转场圆心 / 数据标记？ |
| **不依赖数字** | 在被禁止使用参数对比的前提下，它还能不能证明能力？ |
| **天生自带** | 它是不是主题名里本来就有、不需要另造 logo 的东西？ |
| **可变形** | 它能不能连续 morph 成 5 种以上形态（从而支撑"无剪接"）？ |
| **可静音** | 它能不能承担"停顿"（让 0.4 秒静音看起来是标点而不是事故）？ |

**判据全过 = 母题成立。** 母题选定后全片不许换，所有素材都由它派生。

## 1 · 创意硬约束

1. 第一人称，让观众在 2 秒内知道"你是谁"，在 8 秒内看到"你能干什么"，在 30 秒后记住名字。
2. 只展示 **2–3 个能力**，每个能力用"具体任务 + 具体结果"演出来，不写抽象口号。
3. 开场必须有一个**信息真空**（画面几乎没有东西）然后一次性爆发。
4. 结尾必须**回扣开场**——用同一句话、同一个画面元素。
5. **禁止**：连续翻页式 PPT、长段文字、堆砌无关特效、空喊"我最强"。
6. 允许幽默与自信，但幽默要"降格"（把复杂的东西画简单），不要"亢奋"。

## 2 · 视觉规范（硬性，逐项照抄，不许改数值）

### 2.1 色彩令牌

```
BG       #141413      // 暖近黑，禁止用 #000000
PANEL    #1F1F1D      PANEL2  #2A2926
CREAM    #F0EEE6      // 主文字 / 亮场底色
GREY     #B0AEA5      DIM     #686760
ORANGE   #D97757      // 唯一强调色，全片只此一个
HOT      #FFA880      // 光标、发光核心
GREEN    #7AC478      RED     #EC5450    BLUE #6A9BCC    AMBER #E8B25A
亮场：  LBG #F0EEE6   CARD #FCFBF7   BORDER #DEDBD0   LGREEN #409654
```

**规矩：橙色一帧内覆盖面积不得超过画面的 3%。** 它稀罕，所以它是事件。

### 2.2 字体（四种角色，不许混）

| 角色 | 字体 | 用途 |
|---|---|---|
| 中文标题 | Noto Sans CJK SC **Black** | 最重要的那几句 |
| 正文 | 同族 Bold/Medium/Regular | 次级信息 |
| **机器语汇** | Noto Sans **Mono** CJK SC | HUD、代码、序号、时间码 |
| 拉丁数字/短词 | **Poppins** Bold/Medium | "30%+"、"2026"、"Bug" |
| 品牌名 | **Lora Italic** 600 | 只给主题名里的那一两个拉丁词 |

**字距规则（这是这套视觉的指纹）**：HUD 20px 字号配 **+4.5px** 字距（0.225em）；时间码 +3.5；帧计数 +3.0；**中文正文零字距**。
**中英混排 = 同字号、同基线、换字体。** 不缩小英文、不换行、不加斜体。

### 2.3 字号层级（px @1080p）——跨度必须 ≥ 30 倍

`560` 巨型单字 · `250` 品牌 serif · `150 / 140 / 132` 巨型标题 · `100 / 96 / 84` 宣言 · `72 / 68` 副标 · `46 / 44 / 38 / 34` 清单 · `40` 代码（等宽 20px/字） · `30 / 28` 章节号 · `22` 注释 · `20` HUD · `18` 帧计数。

### 2.4 版式与 HUD 家具

- 安全边距：**左右 76px**。顶栏基线 y=71。帧计数 y=1030。进度条 y=1052，宽 1768。
- 常驻四角：左上 `● <品牌名>`（橙点 + 宽字距小字）；右上 `00:00:00` 时间码；左下 `FRAME 0000 / 0900`；右下 `示意画面`；底边一条橙色进度条。
- 双栏构图：左侧承载"演示"（面板/卡片，约 (120,210)–(1080,810)），右侧承载"结论"（章节号 + 巨型标题 + 清单）。
- **留白率必须 ≥ 88%**（实测像素覆盖率：墨迹占比 ≤ 12%）。
- **HUD 必须吃同一套后处理**——它要跟着画面一起抖、一起色散，不能像贴上去的水印。

### 2.5 后期四层（缺一层就变 PPT 渲染）

1. **辉光**：1/4 分辨率累积层，双高斯 σ=2.2 与 σ=7.0，权重 0.45 / 0.62。
2. **暗角**：椭圆，clip 到 [0.55, 1.0]。
3. **颗粒**：5 张预生成噪声循环，σ=2.2。
4. **抖动 + 色差**：位移 7–26px @34Hz；RGB 通道横移 3–11px。

## 3 · 运动语法：无剪接（cutless）

### 3.1 铁律
**全片 0 次硬切。** 任何两个构图之间的过渡必须由"母题元素的运动"或"同一画面元素的状态变化"承担。剪辑软件意义上的"切"一次都不许有。

### 3.2 允许的六类转场（务必只用这几类）

| 类 | 做法 | 参数 |
|---|---|---|
| **母题 morph** | 同一半径变量插值：点 ↔ 光标条 ↔ 面板 ↔ 圆 | 60×60 → 960×600，圆角 30 |
| **圆形遮罩 iris** | R = 36 + 2400·inout_cubic；**12px 橙边环 + 沿圆周 64 点光环** | 0.5s |
| **粒子重组** | 粒子按**匈牙利算法最小位移**飞向字形；每粒子延迟 0–0.18s；垂直位移加 ±230px 抛物线弧度 | 0.8s |
| **冲击爆发** | 环 30→1540px + 白闪 + 色散 + 抖动**同时**发生 | 0.2s |
| **横向光扫** | 12–16 条亮线 3500–6000px/s 掠过，长 300–900px，宽 2px | 0.4–0.5s |
| **排版 slam** | scale 1.25–2.3 → 1，纵向模糊 26–70px → 0 | 0.24–0.30s |

### 3.3 缓动纪律

- 主力：`out_expo`（快出、慢停）与 `smooth`。次选 `out_cubic`、`inout_cubic`。
- `out_back` 少量（进场过冲），`spring` 极少量（卡片入场）。
- **禁止 `out_elastic`。** 不做弹跳。一个自信的品牌不晃。
- 错峰（stagger）：同一组的元素间隔 **0.08–0.18s**，不要同时出现。

### 3.4 三个必须出现的手笔

1. **slam 砸字**：文字放大 1.25–2.3 倍 + 纵向模糊 70px，0.24 秒收回到 1 倍、模糊归零。
2. **幽灵拖尾**：主角元素画 8–26 个历史位置，alpha ∝ k²。
3. **橙色句读**：中文空心「。」与母题圆点同形。**加一个标点就有重音。**

## 4 · 节奏工程

### 4.1 骨架
**120 BPM → 1 拍 0.5s → 1 小节 2s → 30 秒 = 15 小节。**
所有段落边界必须落在**小节线**上（4.00 / 8.00 / 12.00 / 18.00 / 22.00）。
段落长度采用 **4 / 4 / 4 / 6 / 4 / 8** 秒（对应 蓄力 / 能力1 / 能力2 / 爆发 / 数据 / 落款）。

### 4.2 三段呼吸（必须做，不许一直响）

| 位置 | 时长 | 深度 |
|---|---|---|
| 开场爆点前 | 0.07s | 真·静音，然后一次性 +17dB |
| 主爆点前 | 0.2s | **−48dB 真空**，紧接 −13.7dB（35dB 落差） |
| 落款前 | 0.42s | 静音，画面只剩母题元素在呼吸 |

### 4.3 阅读时间预算（按"字/秒"排期）

- 演示段：**2.6–4.6 字/秒**（舒适阈是 8–10，故意压到一半以下）。
- 落款：**1.0–1.6 字/秒**（几乎静止）。
- **全片不许有任何一句超过 6 字/秒。** 排完写一张"存在窗口 vs 字数 vs 字/秒"的表格自查。
- 顶部钩子句可以赶，但**最多 6 个字**。

### 4.4 结构检查
全片约 26 个构图状态，平均 1.15s 一变。少于 20 个 = 太慢；多于 40 个 = 太碎。

## 5 · 声音工程

- **全合成，零采样**：用 numpy/scipy 写 kick / snare / clap / hat / bass / pluck / marimba / bell(FM) / pad / impact / sweep / chirp + keyclick / blip / buzz / thump / skitter / chime。
- **调性**：小调，i–VI–III–VII 进行；旋律取五声音阶；**唯一的明亮色彩只留给"成功/答复"的那一下**。
- **母带**：目标 −15 LUFS，**真峰值 ≤ −1 dBTP**。流程：写临时 wav → `ffmpeg ebur128` 实测 I → 反算增益 → tanh 软膝限幅。
- **不做采样库、不做版权音乐。**
- **静音是编曲的一部分**：上面 4.2 的三个窗口要用门限真的写成 0。

## 6 · 工程架构（这条决定了你能不能按时交付）

### 6.1 单一时间表
**先写 `timeline.py`，再写第一个镜头。** 它是一张扁平常量表（标量 / 区间 / 列表三种形态），画面和音频**同时 import 它**。
> 目标不是"检查同步"，而是**让不同步变成不可能**。QA 只做事后抽查。

### 6.2 每帧是时间的纯函数
`render_frame(f) = 纯函数(t=f/FPS)`。不许有跨帧状态：
- 拖尾 = 算 `positions(t - 0.022)`
- 打字 = 数时间戳
- 闪烁 = 取模
- 随机 = 固定种子 / 每帧重播种 / 连续函数
> 这样任何一帧都能被单独拉出来审。

### 6.3 文件结构（6–9 个文件，场景之间不许横向依赖）
```
timeline.py    整片时刻表（唯一真相）
gfx.py         动效工具箱：缓动、文字、辉光、圆角矩形、点阵、后期
common.py      HUD、渐变、iris、dot、streak、slam
scenes_a.py    开场 + 演示 1
scenes_b.py    演示 2
scenes_c.py    爆发 + 数据 + 落款
audio.py       合成与母带
render.py      分段渲染 + 管道喂 ffmpeg（支持 `seg a b` 单段重渲）
qa.py          导出检查
build.sh       一键构建
```

### 6.4 审查节奏
- **每写完一个模块立刻 import 冒烟一次。**
- **预览用 contact sheet**：一次拼 20–30 格并在每格烧上时间码，一张图顶十次单帧渲染。
- **长任务先测单帧成本再挂后台**，并给一行可读进度。后台进程必须脱离会话（`setsid + </dev/null + disown`）。

## 7 · 交付与验收（逐条打勾，缺一不算完成）

### 7.1 导出必查四件事
1. **规格**：帧数 = 900、时长 = 30.000s、1920×1080、30fps、音频 48kHz 立体声。
2. **同步**：至少挑 8 个爆点，测画面亮度跳变帧 vs 音频能量峰，**偏差 ≤ ±2 帧**。
3. **响度**：−15 LUFS **且真峰值 ≤ −1 dBTP**（LUFS 达标但 TP 超了就是削波，判不通过）。
4. **清晰度**：**全分辨率**抽帧（不是缩略图），逐个检查文字有无重叠、压字、糊边。

### 7.2 出问题时的修复原则
**回源头改代码再重渲，不许在成品上打补丁。** 900 帧重渲 8 分钟，比在成片上贴一块补丁便宜。

### 7.3 交付物清单
- MP4（可播放，静音看也能懂）
- 完整源代码 + `build.sh`（别人能一键重建）
- 一页 README：主题一句话、时间表、已核实信息清单、技术栈、重新构建步骤
- **一页"我没做的事"**：哪些没验证、哪些是示意、哪些已知缺陷。**诚实是交付物的一部分。**
